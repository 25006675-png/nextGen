LarvaLoop · how the predictions work

Three models, one goal: buy only what you'll use

Every number in the app comes from the shop's own sales history. A simple forecast guesses daily usage, a quantile buffer turns that guess into a safe order size, and a Monte Carlo simulation plays out hundreds of possible weeks to find which stock will expire and how much money will be wasted.

Models 2 and 3 share one extra input: how wrong model 1 was on each of the last 28 days, stored as actual ÷ forecast (e.g. 1.15 = sold 15% more than predicted). This is the backtest.

Model 1 · Demand forecast

Day-of-week moving average

How much chicken will we use next Monday?

  1. Take the same weekday from the last 4 weeks.
  2. Remove holiday effects from those days, then average them.
  3. If the target day is a holiday or festive day, apply its multiplier.

Simple on purpose: it beats "same as last week" and the shop's habit. With more data it can be swapped for Prophet behind the same function.

Output: ~1.03 kg of chicken next Monday
Model 2 · Smart order size

Quantile buffer

Forecast says 3.2 kg until the next delivery. Order exactly that?

  1. Replay the backtest errors 2,000 times to see how much the next 3 days could really need.
  2. Pick a service level: how often the order should be enough. It depends on cost: running out loses about 3× the ingredient in profit, but extra stock only costs money if it spoils before the next delivery.
  3. Order the matching quantile, minus stock already on the shelf that will still be usable, rounded up to the pack size.
Output: order 4 kg instead of the usual 5 kg
Model 3 · Expiry risk and waste forecast

Monte Carlo simulation

Will this tomato batch be used before it expires on Friday?

  1. Simulate 1,000 possible weeks. Each day's sales = forecast × a random past error.
  2. In each week, use the earliest-expiring stock first.
  3. Expiry risk = share of weeks where 5% or more of the batch is still left at expiry.
  4. Waste forecast: the same simulator runs 4 weeks of deliveries under the usual order and the smart order (200 runs each), and counts the RM thrown away.
Output: "Use the tomatoes first: 70% risk of expiring by Friday"
